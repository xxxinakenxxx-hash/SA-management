# 【AIメモSA管理】概要企画書

作成日：2026年10月20日  
文書状態：初稿・承認前  
開発リポジトリ：SA-management

## 1. 企画の背景

営業担当者は日々の営業活動の中で、見積書の作成、資料準備、各種事務処理などをSA（営業支援担当者）へ依頼している。

しかし、依頼を受けるSAは複数名で業務を分担しているため、誰がどの依頼を担当しているか、どこまで進んでいるかを共有できる仕組みが必要である。

特に、担当者の休暇や不在時にも他のSA担当者が対応でき、営業担当者との確認事項や成果物まで一元的に管理できることが望ましい。

一方、既に運用している「営業AIメモ」では、営業担当者が音声入力で商談や業務に関する情報を記録できる。

この仕組みを活用することで、営業担当者が新たな依頼書を作成することなく、SAへの依頼から完了までを管理できる仕組みを構築する。

## 2. 企画の目的

**営業AIメモから登録したSA依頼を、初期導入先である鹿児島営業所のSA担当者全員で共有し、受付・担当・進捗・質問・成果物返却まで一元管理する。**

目指すのは単なる依頼一覧ではなく、SAの日常業務を支える業務管理システムである。

主な目的は以下のとおり。

1. **依頼の見える化**  
   依頼内容、担当者、進捗、対応状況をSA全員が把握できる。
2. **業務の属人化防止**  
   担当者が休暇・不在でも、別のSA担当者が経緯を確認して対応できる。
3. **営業とのやり取りの集約**  
   確認事項や回答を依頼ごとのスレッドに残し、情報の行き違いを防ぐ。
4. **成果物の一元管理**  
   見積書・資料・出荷連絡等の成果を依頼に関連付け、営業へ返却できる。
5. **営業・SA双方の負担軽減**  
   営業は既存の音声入力を活用し、SAは専用画面内で業務を完結できる。

## 3. システムの基本方針

本システムは、全社共通の「営業AIメモ」とは別の、**複数営業所への展開を想定したSA依頼管理システム**として構築する。初期導入先は鹿児島営業所とする。

- 営業AIメモの既存機能は原則変更しない。
- 営業担当者は営業AIメモからSA依頼を登録する。
- SA担当者は専用のWindows向け画面を使用する。
- 営業担当者はスマートフォン対応の別画面で質問への回答や結果確認を行う。
- SA担当者が手動でメールを送らなくても、SA管理画面を開いている間に新着が分かる仕組みと、SAから営業への質問・完了時のGoogle Chat通知を設ける。業務のやり取りは依頼スレッド内で行う。
- 既存の利用者マスターを活用する方向で設計する。

## 4. 利用者と役割

| 利用者 | 主な利用方法 |
|---|---|
| 導入営業所の営業担当者 | SA依頼の登録、進捗確認、質問への回答、成果物の受領 |
| 導入営業所のSA担当者 | 新規依頼の確認、担当引受、進捗管理、営業への質問、資料作成、成果物返却 |
| 管理・設定 | 営業AIメモと同じ管理基準を適用し、SA独自の管理責任者制度を設けない |

SAは複数名で共通の依頼一覧を使用する。

ただし、個別の依頼は原則として担当SAを明確にし、担当変更の履歴も残す。

## 5. 想定する業務フロー

### STEP 1：営業がSAへ依頼する

営業担当者は、既存の営業AIメモから音声またはテキストでSA依頼を登録する。

「SA案件」「SA依頼」という入力表現に対応し、「SA依頼｜内容」の形式で記録する方針とする。

※現行GAS静的調査報告と2026-10-20の保存結果では、`sa_case`は一時分類であり、保存済み記録は`deal_records.deal_theme`の「SA依頼｜」で識別する。

### STEP 2：SA全員に依頼を共有する

登録されたSA依頼を専用システムに取り込む。

新しい依頼はSA担当者の共通一覧に表示され、通知によって新規依頼を把握できるようにする。

### STEP 3：SA担当者が引き受ける

対応するSA担当者が「担当する」を選択し、担当者と対応状況を登録する。

必要に応じて他のSA担当者へ引き継げるようにする。

### STEP 4：作業・営業への確認

SA担当者が作業を進める。

営業への確認が必要になった場合は、依頼のスレッドに質問を投稿する。

営業担当者には自動通知を送り、スマートフォンから回答できるようにする。

### STEP 5：成果物の登録・完了

SA担当者は必要な場合に見積書・資料などを、営業所ごとに設定したGoogle Driveフォルダ（鹿児島は既存Drive配下）へ登録し、取得したリンクを依頼スレッドへ記録する。添付のない依頼も完了コメントで完了できる。

営業担当者は通知から専用画面を開き、結果や成果物を確認する。

### STEP 6：履歴の保存

依頼受付から完了までの担当変更、質問・回答、進捗、成果物の履歴を保存する。

担当SAが不在になっても、別のSA担当者が対応経緯を確認できる。

### 2026-10-23 確定した運用方針

- 営業は鹿児島のSA依頼全件を閲覧し、自分の依頼に絞り込める。投稿は原則として本人が依頼した案件に限る。SAは共通一覧を利用し、SA間の担当変更に承認を要しない。SA独自の管理責任者制度は設けない。
- 1依頼1スレッドで連絡・回答・訂正投稿・成果物リンクを一元管理する。訂正は元の投稿を残して新たに追記する。
- カードとスレッドは独立し、投稿や返信だけで進捗を変更しない。カードの進捗は明示操作によって変更する。完了後も再開できる。
- 営業AIメモからのSA依頼識別IDのみを新側でリンクする方式を優先検証する。実DBの連携テストは未実施であり、性能や方式の確定を意味しない。
- AIサービス・送信する情報の範囲・費用は検討後に別途承認を受ける。現時点では外部送信・課金未承認。

## 6. 管理する進捗ステータス

| ステータス | 意味 |
|---|---|
| 未担当 | 依頼が登録され、SA担当者が決まっていない |
| 対応中 | SA担当者が作業している |
| 営業回答待ち | SAからの質問に対する営業の回答を待っている |
| 完了 | SAの対応が終了し、結果を返却した |

完了状態はロックを意味せず、対応中への再変更を認める。担当変更はカード側の独立操作とする。

## 7. 画面構成

### 7-1. SA専用画面（Windows）

既に作成したHTMLモックの3カラム構成を基本として採用する。

| 左カラム | 中央カラム | 右カラム |
|---|---|---|
| 依頼一覧 | 依頼詳細 | 営業とのスレッド |
| 未担当・対応中などの絞込 | 担当者・進捗変更 | 質問・回答 |
| 未読・新着の確認 | 作業内容・完了処理 | PDF・成果物 |
| 依頼検索 | 対応履歴 | 関連ファイル |

**SA担当者が日常業務を1画面で進められること**を重視する。

デザインは、一般的な管理システムよりも洗練された、AIサービスのような視認性と操作性を目指す。

### 7-2. 営業担当者用画面（スマートフォン）

営業担当者には専用のスマートフォン対応画面を設ける。

主な機能は以下とする。

- 自分が依頼した案件の確認
- 現在の対応状況の確認
- SAからの質問への回答
- スレッドの閲覧
- 完了結果・PDFの確認

営業AIメモ本体へ新たなスレッド管理機能を追加する方式は採らない。

## 8. システム構成

本システムでは、既存のGoogle Workspace環境を活用する方針とする。

| 技術 | 主な役割 |
|---|---|
| Google Apps Script（GAS） | 業務処理、依頼連携、データ操作、通知制御 |
| Googleスプレッドシート | 依頼・担当・進捗・スレッド・履歴の保存 |
| Google Drive | PDFなどの成果物保管 |
| HTML・CSS・JavaScript | SA画面・営業画面 |
| PWA | Windowsで利用しやすいアプリ形式 |
| GitHub | ソースコード・正本・開発履歴の管理 |

新SA管理は保存済みの`deal_theme`と`original_text`（必要に応じ`deal_content`）から「誰に／何を／依頼の種類／決まっていること／いつまで」をAIで構造化し、元文章を保持する。AIの利用サービス・社外送信・費用、データ連携・認証・通知の具体方式は未確定事項確認書で管理する。

SAへの新着通知はSA管理画面の起動中だけに表示する。閉アプリ・閉画面向けWeb Pushは初期要件外とし、画面内の更新方式を後続設計で確認する。

## 9. 導入によって期待する効果

### 営業担当者

- 音声入力を活用してSAへ依頼できる。
- 依頼の進捗を自分で確認できる。
- SAからの質問へスマートフォンで回答できる。
- 完成した資料を依頼ごとに受け取れる。

### SA担当者

- 新規依頼の確認漏れを減らせる。
- 担当者と進捗が明確になる。
- 不在時の引継ぎを容易にする。
- 営業とのやり取りを依頼単位で確認できる。
- 複数の依頼の優先順位や対応状況を把握しやすくなる。

### 営業所全体

- SA業務の可視化
- 依頼の滞留防止
- 業務負荷の把握
- 対応履歴の蓄積
- 営業とSAの連携強化

※具体的な削減時間や定量効果は、現状業務の実績が未確認のため設定しない。

## 12. 企画のまとめ

本企画は、営業AIメモに蓄積されたSA依頼を、実際の業務処理につなげるための仕組みである。

営業担当者は新たな入力負担を増やさず、SA担当者は専用画面で業務を管理する。

**「依頼する → 担当する → やり取りする → 完了する → 結果を受け取る」**

この一連の流れを一元化することで、鹿児島営業所の営業活動を支援する。

まずは鹿児島営業所で導入し、現場での実運用を通じて改善する。将来的には他営業所でも利用できる共通設計とする。

## 2026-10-26 確定方針（本文の旧記述に優先）

- **カードとスレッドは独立**：スレッドへの投稿・返信・訂正・閲覧を理由にカードの担当者や進捗を自動変更しない。進捗はカード側の明示的操作で変更する。Google ChatはSAから営業への質問・完了の通知手段であり、業務データやカード進捗の変更契機ではない。
- **完了は制約としない**：「完了」から再び対応中などへ変更可能とする。完了をロック・不可逆状態にしない。PDF等の添付0件でも完了可能。
- **期限表現**：「今日中」「明日まで」「今週中」「今週末」「来週中」「○曜日まで」を入力・依頼基準日からカレンダー日付として解釈する。「なるべく早く」は期限上の至急指定として扱い、架空の日付を作らない。原文と解釈結果を保存し、曖昧な場合は確認・訂正可能とする。
- **モック機能**：担当別は既存一覧の担当者選択・絞込で切替し独立画面を追加しない。営業所別Drive保存先は営業所ごとの設定値で管理し、独立した設定画面を要件として追加しない。備考欄はSA業務メモとして正式採用し、完了コメントと区別して保存・再表示する。期限は一覧表示・絞込・注意表示とし、期限接近を理由とする自動通知は追加しない。ダッシュボードは既存KPI・一覧絞込の範囲で扱い、独立画面を新設しない。
- **管理・保存**：営業AIメモと同じ管理基準を適用する。SA管理独自の管理責任者・管理者ロール・承認制度・保存期限・自動削除を新設しない。必要な技術的認可・障害復旧・バックアップは既存基準と整合させて設計し、別の管理制度と混同しない。
- 上記は利用者が承認した**業務・設計方針**であり、API/DB実装や実通信・実機試験が済んだことを意味しない。

## 2026-10-26 追加確定方針（SA-003・SA-020）
- **SA-003：既存社員・営業所マスターは営業AIメモ側を直接参照するB案を採用。** SA管理DBへマスターを複製・同期しない。既存マスターの参照権限・キー・安全な接続方法は実装前に技術確認する。
- **SA-020：AIによる5項目抽出にOpenAI APIを採用するB案を確定。** Gemini等との選定比較をユーザーに再要求しない。具体的なOpenAIモデル、送信対象の顧客情報、データ取扱い、料金見積り、認証と失敗時処理を設計・検証する。**OpenAI APIの採用決定は、実データの外部送信・課金開始・APIキー利用の許可ではない。**
