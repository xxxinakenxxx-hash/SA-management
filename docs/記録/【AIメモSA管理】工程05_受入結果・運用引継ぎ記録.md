## 4. 運用の手順

### 4.1 設定（スクリプトプロパティ。値はGitHubや報告に書かない）

| 名前 | 用途 |
| --- | --- |
| `SALES_DB_ID` | 営業AIメモDBのスプレッドシートID（読み取りのみ） |
| `AI_API_KEY` | OpenAIのAPIキー |
| `SA_IMPORT_BRANCH` | 取込対象の営業所名（任意。未設定なら鹿児島） |
| `SA_CHAT_WEBHOOK_<営業のメールアドレス>` | その営業へのChat通知の送り先 |
| `SA_APP_URL` | 通知に付ける画面のアドレス（任意。取れないとき用） |

営業所のDriveの保存先は、SA画面の「保存先設定」で登録します（シート `sa_branch_settings` に追記されます）。

### 4.2 営業へのChat通知の送り先を登録する
1. 営業がChatで、通知を受け取るスペース（または自分とのDM）の「アプリと統合」→「Webhook」→「Webhookを追加」で、名前「SA管理通知」のWebhookを作る。
2. 横の**コピーボタン**でURLをコピーする（手で打たない。`&` が `&amp;` に変わらないようにする）。
3. 稲森さんが、スクリプトプロパティ `SA_CHAT_WEBHOOK_<その営業のメールアドレス>` に、URL全体を貼って保存する。前後に空白や改行を入れない。
4. **Webhookを削除しない**（削除すると、トークンが無効になり400になる。2026-11-12に実際に発生）。
5. 登録後は、最小の確認メッセージ1通で届くことを確認する。

### 4.3 日常の見方
- 取込：シート `sa_import_log`（success／duplicate／failed）。5分ごと。
- AI抽出：シート `sa_requests` の `extraction_status`（complete／needs_review／failed／pending）。`needs_review` は5項目のどれかが空欄で、SAが原文を見て確認する。
- 通知：シート `sa_notifications` の `delivery_status`（sent／failed）と `last_error_code`（`HTTP_<番号>`、`WEBHOOK_NOT_SET`、`WEBHOOK_INVALID`、`SEND_ERROR`）。

## 5. 障害時の対応

| 症状 | 確認する場所 | 対応 |
| --- | --- | --- |
| SA画面が開かない | 本番のアドレスが `…/s/<本番のデプロイID>/exec`（組織のドメイン付き）か。会社アカウントで開いているか | 試験用の公開のアドレスを案内していないか確認。公開一覧に本番のIDが残っているか確認 |
| 営業が登録したのにSA一覧に来ない | `sa_import_log`。トリガーの実行履歴 | トリガーが削除・停止されていないか確認。件名が「SA依頼｜」で始まり、対象営業所か確認。`failed` ならエラーコードで原因を調べる |
| AI抽出が `failed`、`pending` のまま | `sa_requests` の `extraction_status` | `failed` は自動では再実行されない。**再実行の手段は、現状のコードにありません**（§6）。SAは原文を見て手で対応できる |
| 通知が届かない | `sa_notifications` の `last_error_code` | `WEBHOOK_NOT_SET`：送り先が未登録→§4.2。`HTTP_400`：トークン不正（Webhookの削除・作り直し・コピーの文字違い）→Webhookを作り直して貼り替え。貼り替え後、Apps Scriptのエディタで `resendFailedNotifications` を実行すると、失敗・保留の通知を再送する |
| 添付が保存できない | 画面の案内・`sa_branch_settings` | 保存先が未設定なら「保存先設定」でDriveフォルダを登録。共有が広いフォルダは拒否される |
| 更新後に不具合 | 直前の公開の版 | `clasp deploy -i <本番のデプロイID> -V <戻したい版>` で版を戻す。続けて原因を調べる |
