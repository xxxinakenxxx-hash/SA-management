## 2. 採用方式（SA管理の実装方式）

1. 画面：GASの中に画面を置く（`HtmlService.createTemplateFromFile` ＋ `evaluate`、`google.script.run`、`doGet` の `view` パラメータで切り替え）。営業AIと同じ作り。スマホ向けに `viewport` を指定する。本番の画面を GitHub Pages に置かない（ユーザー決定）。
2. 本人判定：`Session.getActiveUser().getEmail()` を営業AIの `user_master.user_key` と突き合わせる（営業AIと同じ）。SA＝`sales_support`、営業＝`sales`（ユーザー確認済み）。マスターは複製せず直接参照する。
3. 営業AIの表の読み取り：Sheets API（`spreadsheets.readonly`）。`SpreadsheetApp.openById` は編集権限（`spreadsheets`）を要求するため使わない。
4. SA管理の表の読み書き：`spreadsheets.currentonly`（GASが紐づくSA管理表だけ）。
5. 同時操作：`LockService.getScriptLock` ＋ `row_version` の比較。複数セルの書き込みの途中で失敗した場合は、巻き戻し（補償）で整合に戻す。
6. Drive：`drive.file`（このアプリが作ったファイルだけ扱える）。営業AIのファイルには触れない。
7. OpenAI：営業AIと同じ `gpt-4o-mini`、キーはスクリプトプロパティ `AI_API_KEY`、`UrlFetchApp` で呼ぶ。5項目はJSONスキーマで受け取り、返りの文字列「null」を取込時に正規化する。4xxは再試行せず、429・5xxだけ待ち時間を倍にして再試行する。
8. 新着：画面を開いている間だけ、3秒ごとの問い合わせ（`google.script.run`）。
9. PWA：採用しない（⑨）。
10. 必要な権限（SA管理GAS）：`spreadsheets.readonly`、`spreadsheets.currentonly`、`drive.file`、`script.external_request`（OpenAI・Chat用）、`userinfo.email`。これを超える権限は使わなかった。
