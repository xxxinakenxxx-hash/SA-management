## 1. 目的

現在の鹿児島営業所の運用を維持し、北九州営業所に加えて長崎営業所のSA依頼も同じ仕組みで自動取込できるようにする。長崎の説明会を北九州より先に実施するため、長崎の準備を優先する。

長崎営業所では2026-11-24に説明会を予定している。**説明会と本番利用開始は別であり、両営業所の利用開始日・順序は未確認**とする。

**取込対象営業所をGASコードや単一のスクリプトプロパティで管理せず、SA管理スプレッドシート上で有効・無効を切り替えられる方式へ変更する。** 将来、営業所を追加する際も、原則として営業所名のコード修正・再デプロイを不要にする。

## 3. 改修方針

### 3.1 取込対象は専用シートで管理する

SA管理スプレッドシートに取込設定専用のシート `sa_import_targets` を追加する計画とする。

| 列 | 項目 | 用途 |
|---|---|---|
| A | `branch_name` | 営業AIメモDB `deal_records.branch_name` と一致させる営業所名 |
| B | `import_enabled` | `TRUE`＝自動取込対象、`FALSE`＝自動取込対象外 |

**段階別設定案（2026-11-20に `user_master` で確認済みの6所属区分＋今回追加する長崎）**

| branch_name | 長崎を先に利用開始する場合 | 北九州も利用開始した場合 |
|---|---|---|
| 鹿児島 | TRUE | TRUE |
| 長崎※ | TRUE | TRUE |
| 北九州 | FALSE | TRUE |
| 福岡本社 | FALSE | FALSE |
| 熊本1課2課 | FALSE | FALSE |
| 関東販売 | FALSE | FALSE |
| 丸菱ＨＤ | FALSE | FALSE |

- ※「長崎」は計画上の表記。設定シートには営業AIメモDB `deal_records.branch_name` と一致する**確認済みの正式値**を登録する。現在は未確認。
- **上表は長崎を先に利用開始する場合の条件付き設定案であり、利用開始の順序は確定していない。** 実際は各営業所の利用開始が決まった時点で、その営業所だけを `TRUE` にする。
- 2026-11-20に `user_master` で確認した6区分には長崎は含まれていなかった。`branch_master` は見出しのみで所属データがないため、ここに挙げた7区分を全社の正式な拠点一覧とは断定しない。
- `TRUE` / `FALSE` は**共通DBへの自動取込のON/OFFだけ**であり、SA管理画面・営業画面の閲覧権限や表示対象は変更しない。説明会だけでは設定を切り替えない。

- 取込対象の追加・有効化・停止はシートの行・値で操作し、営業所名をGASへ直接追記しない。
- 同じ営業所名が重複登録された場合、値が不正な場合、シートが存在しない場合は設定エラーとして扱い、推測で取込対象を決めない。
- **既存の `sa_branch_settings` はDrive保存先の設定履歴を管理しているため、変更しない。** 取込ON/OFFとDrive保存先を同じ設定行へ混在させない。
- シートの編集権限は既存のGoogle Sheets権限で管理する。新たな管理画面は作らない。

> 前回の準備段階で挙げた「`sa_branch_settings` に取込設定列を追加する案」は、本計画では採用しない。Drive保存先の変更履歴と自動取込の設定を独立させるためである。

### 3.2 5分ごとの既存トリガーを維持する

`runScheduledImport()` は、専用シートから有効な営業所一覧を取得し、営業所ごとに既存の取込・AI抽出関数を呼ぶ方式に変更する。

```text
既存の時間主導トリガー（5分ごと）
  ↓
sa_import_targets から TRUE の営業所を取得
  ↓
営業所ごとに処理（設定シートの正式 branch_name）
  ├─ importSaRequests_(branch_name)
  └─ extractPendingRequests_(10, branch_name)

各営業所の利用開始時に、その営業所の設定を TRUE にして取込対象へ追加
```

- トリガーを営業所数だけ増やさない。
- 各営業所の処理結果を営業所別に確認できる形で返し、必要な実行ログを残す。個人情報や秘密情報をログへ出さない。
- ある営業所の処理に失敗しても、可能な限り他営業所の処理を継続する。失敗を成功扱いにしない。
- 既存の取込重複防止、1営業所当たり1回最大10件の抽出、保存済み依頼・履歴を維持する。

## 4. 変更対象と非変更対象

### 変更対象

| 対象 | 変更内容 |
|---|---|
| SA管理DBの新規シート `sa_import_targets` | 取込対象営業所と有効・無効の管理 |

- 営業AIメモ本体、`deal_records`、`record_id` 採番方式
- `gas/02_source.js`、`gas/03_import.js`、`gas/04_extract.js` の既存の営業所別処理
- `sa_requests` の既存データ・ステータス・アーカイブ機能
- `sa_branch_settings`、Drive保存先設定、添付処理
- SA・営業の画面、認証・権限、スレッド、通知、完了処理
- 既存の5分間隔トリガーの周期

正本の変更が必要な箇所は、改修対象・設計方針の確定後に、既存の正本本文と照合して必要部分だけ反映する。既存正本を無断で書き換えない。

## 8. 切戻しと停止条件

- 切替前の本番デプロイバージョン、mainのコミット、設定シートの内容を確認してから反映する。
- 鹿児島の自動取込に障害が出た場合は、**事前に確認した直前の本番デプロイ版**への切戻しを検討する。元の `SA_IMPORT_BRANCH` を無断削除せず、旧版での動作条件を維持する。
- 新規設定シートは切戻し後も残してよいが、既存のSA依頼データ・Driveフォルダ・通知履歴を削除しない。
- 正本との矛盾、既存機能の回帰不合格、許可範囲外の変更が必要になった場合は停止して報告する。

## 9. 完了判定

次の状態を**長崎・北九州それぞれの利用開始時に判定**する。一方の確認が完了しても、他方を完了扱いしない。
