## 2. 作るもの・対象

SA向け既存画面に「改善・不具合を報告する」ボタンを追加し、営業AIメモの既存受付フォームS-07を開けるようにする。既存画面のレイアウトを維持し、配置は改訂された画面設計書に従う。

## 3. 実施事項

1. SA向け画面の既存実装ファイルを特定し、正本で確定した位置にボタンを追加する。
2. 遷移先を、営業AIメモの稼働中デプロイAの`view=feedback`に設定する。既存の認証・画面表示・保存処理を使う。
3. SA画面からボタン押下 → 既存S-07表示 → 既存API-43を介した営業AIメモ_DB「改善不具合対応」への保存まで、該当範囲を確認する。
4. 他のSA依頼管理機能への変更がないことを検査する。

## 4. 許可範囲・禁止範囲

- 許可：SA側の指定ボタン／既存フォームへの遷移を加える局所的なUI変更と検査。
- 禁止：SA側に同フォームを複製すること、新しい受付APIやDB書込処理を作ること、既存の営業AIメモの認証・権限を変更すること、SA依頼・会話・状態・成果物・通知や既存データを変更すること、未承認の本番反映。
- 正本・開発工程表にない追加仕様や独自の画面・業務機能を作らない。

## 5. 検査・反映

- SA画面のボタンが表示され、営業AIメモの同じS-07へ遷移すること。
- 既存S-07から既存DBへの記録が正しく行われること。
- 既存のSA管理機能が従来どおり動くこと。

差分・構文・リンク先を検査し、許可済みのGitHub経路でmain反映と再取得照合を行う。GAS反映が許可された工程なら`clasp push --force`、デプロイ更新は指定条件を確認してから実施する。未実施事項を成功と記録しない。
